# Автоматизация цеха 3D-печати

Приложение `printer3d` для 1С:Предприятие.Элемент, режим совместимости `10.0`.
Исходники находятся в `print_tech/printer3d/`. Правила работы с репозиторием — в [AGENTS.md](AGENTS.md).

## Соответствие архитектуре

Метаданные дополнены по двум страницам схемы `.local/inbox/Автоматизация цеха 3D-печати.drawio`.
Исходная схема находится в локальной папке, исключённой из Git.

| Область схемы | Объекты проекта |
|---|---|
| Продукция, материалы и принтеры | Справочник `НСИ/Номенклатура`, перечисление `ТипыНоменклатуры` |
| Марка, цвет, тип пластика | Справочники `Марки`, `Цвета`, перечисление `ТипыПластика` |
| Поставщики и покупатели | Справочник `НСИ/Контрагенты` |
| Менеджер и мастер смены | Справочник `НСИ/Сотрудники`, ссылки в документах |
| Покупка принтеров и материалов | Документ `Товародвижение/Покупки`, регистр накопления оборотов `ПокупкиНоменклатуры` |
| Поддерживаемый принтером пластик | Регистр сведений `НСИ/СовместимостьПринтеровИПластика`: принтер + тип пластика → признак поддержки |
| Размеры рабочей области | Реквизиты `ШиринаПечатиМм`, `ГлубинаПечатиМм`, `ВысотаПечатиМм` справочника `НСИ/Номенклатура` |
| Состояние принтера | Перечисление `НСИ/СостоянияПринтера`, периодический регистр сведений `Производство/СостоянияПринтеров` |
| Остатки материалов в цехе | Регистр накопления остатков `Товародвижение/МатериалыВЦехе` |
| Остатки материалов в принтере | Регистр накопления остатков `Товародвижение/МатериалыВПринтерах`: принтер + материал → количество граммов |
| Заказ клиента | Документ `Производство/ЗаказыКлиентов`, табличная часть `Продукция` |
| Статусы и учёт заказов | Перечисление `СтатусыЗаказа`, регистр сведений `Производство/УчетЗаказов` |
| Распределение производства по принтерам | Документ `Производство/Производство`, табличная часть `Продукция` |
| Прогноз времени и загрузка оборудования | Регистр сведений `Производство/ЗагрузкаОборудования` |

Легенда схемы содержит категорию «Константы», но конкретных констант на ней нет, поэтому набор констант не добавлен.

## Принятая модель данных

- Принтер — позиция `Номенклатуры` с типом `Оборудование`. Для раздельного учёта двух физических принтеров нужны две позиции номенклатуры.
- Материал — позиция номенклатуры с типом `Материал`; её тип пластика, цвет и марка хранятся в существующих реквизитах.
- Остатки и расход материалов хранятся в граммах, размеры — в миллиметрах, длительность печати — в минутах. Количество оборудования и продукции задаётся в штуках. В строках покупки единица количества определяется типом номенклатуры.
- В производстве каждая строка связывает продукцию, принтер, материал, расход и плановое время печати. В регистре загрузки поле `НомерЗадания` различает строки одного документа на одном принтере.
- Размеры области печати задаются непосредственно в карточке номенклатуры с типом `Оборудование`. Для остальных типов номенклатуры эти реквизиты не используются. Совместимость пластика хранится в отдельном непериодическом регистре; состояния принтеров — с периодичностью `Момент`. Учёт заказов и загрузка оборудования — независимые непериодические регистры.
- Для `ПокупкиНоменклатуры` тип регистратора — `Покупки.Ссылка?`; для обоих регистров остатков — `Покупки.Ссылка|Производство.Ссылка|?`. Это описание допустимых документов, алгоритмы их движений ещё не определены.
- Новым документам и регистрам установлен доступ `РазрешеноАутентифицированным`. Существующие настройки доступа справочников сохранены.

## Текущий этап и проверка

Реализована структура метаданных и включён автоинтерфейс подсистем. Существующие UUID сохранены. Для межподсистемных ссылок настроены `Импорт`, `Использование` и видимость объектов.

По договорённости код движений пока отсутствует. Суммы, статусы, время окончания печати и записи регистров автоматически не рассчитываются и не синхронизируются. Проверки типа номенклатуры, совместимости пластика, размеров, пересечений заданий и достаточности остатков будут частью следующего этапа.

При установленном наборе `xbsl-ai-skills` метаданные проверяются из корня репозитория:

```sh
python3 ~/.codex/skills/xbsl-validate/scripts/validate.py print_tech --format text
git diff --check
```

Локальный валидатор не заменяет сборку в среде 1С:Предприятие.Элемент. После загрузки исходников проверьте сборку проекта, появление разделов и форм, ввод документов и доступ пользователей. До реализации движений сохранение документов не меняет остатки.
